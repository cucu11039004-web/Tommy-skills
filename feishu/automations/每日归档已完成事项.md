# 每日归档已完成事项

调度：`0 22 * * *`，每天 22:00（Asia/Shanghai），云电脑运行。

## 提示词原文

文档链接与租户域名已替换为 `<…>` 占位符。

```
本次请求是由「每日归档已完成事项」定时任务到时触发的。每天 22:00（Asia/Shanghai）固定运行，将《待办事项》中用户已勾选的完成事项迁移到《已完成事项》，先归档、验证，再删除原待办；用户新增事项只添加到《待办事项》。源文档：https://<租户域名>/docx/<待办事项 token>；目标文档：https://<租户域名>/docx/<已完成事项 token> 。《待办事项》保持竖排，只允许三个一级标题：“项目研发”、“日常办公”、“其他休闲”。《已完成事项》使用一个两列网格，从左到右固定为“项目研发”、“日常办公”，只允许这两个一级标题，不得创建“其他休闲”分类、子标题或其他解释性段落。归档映射为：“项目研发”写入“项目研发”列，“日常办公”写入“日常办公”列，“其他休闲”也写入“日常办公”列。每次重新读取两份最新文档，仅处理源文档 done=true 的复选框；保留任务文本和链接，以 done=true 的复选框形式插入目标文档对应列内的一级标题正下方、该列既有完成记录之前，保留删除线，不得在网格外或文档末尾追加。按归档时间倒序排列：每次运行新迁移的批次置于对应列最前；同一批次内按源文档中的先后顺序排列，包括“日常办公”和“其他休闲”同时归入“日常办公”列的情况。每条新迁移记录必须在任务文本前添加实际运行日期，格式为“YYYY年M月D日｜任务内容”，例如“2026年11月7日｜任务内容”，日期使用 Asia/Shanghai 时区下任务实际运行日期，不写具体几点几分，不单独创建日期标题。现有无日期历史完成项保持原样，不回填日期，也不因倒序规则重排或改写。按目标分类、同一日期、同一任务文本去重，允许同一任务文本在不同日期分别归档。归档后重新读取目标文档验证；只有验证成功才删除源文档中对应复选框。归档失败、无法验证或文档冲突时不删除源任务，不改动未勾选项、源文档三个一级标题及目标文档两列网格结构。没有已勾选事项时也正常完成检查，但不修改任何文档，不添加空日期或空标题。最后报告迁移数量、源分类与目标分类的对应结果和失败项；若授权失效，明确提示重新授权且不反复重试。权限范围仅为读取和编辑上述两份指定文档。
```
