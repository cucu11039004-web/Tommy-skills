# 每日文档归档与台账同步

调度：`0 21 * * *`，每天 21:00（Asia/Shanghai），云电脑运行。

## 提示词原文

知识空间 ID、Wiki 节点、多维表格 token 与租户域名已替换为 `<…>` 占位符。

```
本次请求是由「每日文档归档与台账同步」定时任务到时触发的。请执行以下完整任务：

【总体目标】把云盘根目录当作收件口、云盘「收件箱」当作单层中转站、我的文档库当作唯一归档真身、多维表格当作索引，跑完一轮后云盘根目录与收件箱都保持干净（不含任何快捷方式壳子）。每天运行一次。

1) 查/建收件箱：目标为云盘根目录下的「收件箱」。先在云盘根目录（folder_token 为空）按名称查找是否存在「收件箱」文件夹；不存在则用 lark-cli drive +create-folder 在根目录创建。收件箱必须保持单层，禁止在其内部创建任何月份子文件夹（如 2026-11）或日期子文件夹（如 11月07号），无论是否存在都不创建。

2) 搬运入箱：用 lark-cli drive files list 读取云盘根目录的直接子项，只把 type=docx（飞书在线文档）用 lark-cli drive +move 移动进「收件箱」。跳过 bitable 本体（《文档审阅台账》base_token=<台账 base_token>）和文件夹；sheet、bitable、pdf、图片、附件等一切非 docx 条目一律不移动、不删除，仅记入汇报的「未处理清单」。此步骤是普通移动，不产生快捷方式。

3) 按录音分组：同一次录音会产出多篇文档，以标题里的时间戳为组号（例如「文字记录：soundcore Work_11-06 17:57」「智能纪要：soundcore Work_11-06 17:57」「我的笔记：soundcore Work_11-06 17:57」同属一组）。必须整组一起迁移，禁止只搬智能纪要而把文字记录、我的笔记落在原处。

4) 迁入我的文档库（个人知识库 space_id=<文档库 space_id>），用 lark-cli wiki +move 的 docs_to_wiki 模式执行，全任务只有两个去向：
   a. 录音类（录音豆产出的智能纪要、文字记录、我的笔记等，整组）→ 纪要汇总（node <纪要汇总 node>）下的「soundcore 汇总」（node <soundcore 汇总 node>），直接放入，不再细分「soundcore 工作」「其他讨论」之类的子分类。
   b. 其余所有 docx（豆包工作总结等）→「项目文档」主目录，即作为「项目文档」节点（node <项目文档 node>）的直接子文档。严禁放入其下的「算法」（node <算法 node>）、「硬件」（node <硬件 node>）、「工具流」（node <工具流 node>）任一分类，具体分类由用户后续自行处理。
   归属判断以标题和正文为准；拿不准的不硬塞，留在收件箱并在汇报中单独列出。

5) 清理中转残留：迁移完成后，用 lark-cli drive files list 读「收件箱」，只删除 type=shortcut 的条目（lark-cli drive +delete --type shortcut --yes）。遇到 docx 等其他类型一律跳过，绝不删除正文。收件箱清空后保留文件夹本身，不要删除收件箱文件夹。

6) 清理云盘根目录历史快捷方式壳子（作为兜底）：根目录清单接口不返回 shortcut，必须用 lark-cli drive +search --doc-types shortcut 按多组关键词分别搜索（至少覆盖：智能纪要、文字记录、我的笔记、方案、总结、手册、指南、需求、计划、报告、清单、流程、记录，并按本轮归档文档标题补充关键词），合并结果按 token 去重。对每个命中项取其 result_meta.token，串行执行 lark-cli drive +delete --file-token <token> --type shortcut --yes。只删除 SHORTCUT 类型条目，其他类型一律跳过。注意搜索索引有延迟：删除是否生效以命令返回 deleted=true 或错误码 1061007（file has been delete）为准，不要因为搜索接口还能搜到就重复删除或误判失败。

7) 更新《文档审阅台账》多维表格（base_token=<台账 base_token>，表 <台账 table_id>）：为本轮归档的每篇文档补录记录，字段包括文档名称、分类、来源（录音豆 或 豆包工作）、文档链接、创建时间、最近更新、审阅状态=待审阅、备注含归档位置。分类字段只允许两种取值：「录音纪要」「项目文档」（不再使用 soundcore 工作、其他讨论、个人管理等旧分类）。台账中已不存在（被删除）的文档标记或清理，保持台账与文档库一致。

8) 完成后向用户汇报：本次归档 N 篇（其中录音 N 组、项目文档 N 篇）、未处理的非 docx 条目 N 项（逐项列出名称与类型）、清理中转残留 N 条、清理根目录壳子 N 条、台账新增/更新 N 条，并给出台账链接 https://<租户域名>/base/<台账 base_token>。

【注意事项】迁移前确认目标目录与节点；文档移动后链接不变，权限随知识库继承；录音音频本体在妙记中，不随文档移动受影响；缺少权限的文档不要反复重试，记录后在汇报中说明；某一步失败不影响其余步骤继续执行，失败项在汇报中说明。
```

第 6 步命令里的 `<token>` 是原文自带的变量，指每个搜索命中项的 token，不是脱敏占位符。
