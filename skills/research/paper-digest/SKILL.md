把一篇论文写成一份别人五分钟能读完、你自己三个月后还能看懂的中文笔记。两步：先通读并问清用户想看什么，再按模板写。

## 输入

- 接受一篇论文：arXiv 链接（abs、pdf、html 任一形式，归一为 arXiv id）或本地 PDF 路径。
- 一次只处理一篇。收到多篇时回复「一次只处理一篇，请分开调用」并停止。
- 只收到标题时索要链接或 PDF，不自行搜索。
- 命令里若已写明「关注点：…」或「对比：<链接或路径> 维度：…」，视为步骤一的两题已答，直接进步骤二。

## 步骤一：通读并提问

1. **通读全文。** 本地 PDF 直接读；arXiv 链接优先读 `https://arxiv.org/html/<id>`，没有 HTML 版则下载 PDF 读。实验章节的每张表都要读到：主指标和消融数字只能来自表格。本地 PDF 先抽文本；老期刊的表格常是图片、抽不出数字，这时把含表的页面渲染成图再读。
2. 读到实验章节时记下主指标表和消融表所在页码，步骤二裁剪截图用。
3. 用两三行说明这篇论文做了什么，并列出 3 个值得深挖的**候选角度**。候选角度来自论文本身的具体内容（某个设计选择、某组反直觉的实验结果、某个作者一笔带过的假设），不是「可以扩展到更多场景」这类泛泛方向。
4. 一次问两题，然后停下等用户回答。有交互式提问工具就用它把两题放在一次提问里；没有就用纯文本列出两题。
   - **关注点**：选一个候选角度、自己填一个、或答「无」。
   - **对比论文**：给出链接或 PDF 路径以及想对比的维度，或答「无」。
5. 用户给了对比论文，就用同样的方式通读它的全文。

完成标准：两题都有明确答案，「无」也是答案。

## 步骤二：写笔记

按 [references/template.md](references/template.md) 的节次和每节的写作要求写，风格对齐 [references/example.md](references/example.md)。

- 两题都是「无」：只写模板的基础节。
- 有关注点：在「限制」之前加「针对关注点」节。
- 有对比论文：在「限制」之前加「对比」节，位于「针对关注点」之后。

### 输出位置

每篇论文一个文件夹：`~/Documents/论文分享/<YYYY-MM-DD>-<方法简称>/`，日期是今天。文件夹已存在先问用户覆盖还是另存。文件夹顶层只有两个文件，图片全部在 `assets/` 里：

- `<方法简称>.md`：笔记。
- `<方法简称>.pdf`：论文原文。输入是本地 PDF 就复制过来；输入是 arXiv 链接就从 `https://arxiv.org/pdf/<id>` 下载。
- `assets/fig1.png` 放 Figure 1，`assets/arch.png` 放架构图，架构图按内容判断，通常是 Figure 2。图只裁图本身，不含原文图注；arXiv 论文可直接下载 HTML 页面里的原图（页面源码 `<img src>` 的相对路径拼在 `https://arxiv.org/html/<id>vN/` 后），本地 PDF 则按图的区域裁剪。拿不到的图在原位写「见原文 Figure N」，不放占位图。
- `assets/table_main.png` 放主指标表、`assets/table_ablation.png` 放消融表，从 PDF 对应页面按表格区域裁剪，含表标题和表注。截图的像素宽度跟着表在页面上的物理宽度走：单栏表约 1000 px，通栏表约 1800 px，几行几列的小表约 700 px，这样贴进文档时小表不会撑满一行。笔记里的指标数据只以截图呈现，不手工重建表格。

笔记里用相对路径 `assets/…` 引用图片。

写完笔记后，在 `~/Documents/论文分享/INDEX.md` 的表格末尾追加一行：日期、方法名、一句话解释（截到 40 字以内）、标签、指向笔记的相对链接。INDEX.md 不存在就按 [references/template.md](references/template.md) 末尾的格式新建。

### 事实规则

- 正文里引用的每个数字出自论文表格，保持原文精度和单位。表格本身用原文截图，不自己重建。
- 论文没做消融就写「论文未做消融」。多个数据集时主指标表只放最常被比的那个 benchmark，其余各用一句话。
- 对比论文中凭记忆而非原文写出的内容标「未核对原文」。
- 「针对关注点」节里每个论断指向原文位置（章节号、公式号或图表号）。论文没直接讨论时写明「论文未直接讨论，以下基于 X 推断」。

### 写法

- 标题用 Markdown 层级：文档名 `#`，各节 `##`，节内小标题 `####`。正文首次出现的模块名、指标名、方法名加粗。
- 图下一行斜体图注「*Figure N：原文图注的中文概括*」，一句话。Figure 1 用 `<img src="assets/fig1.png" width="600">` 缩小显示，架构图用普通 Markdown 图片语法不缩。表格截图自带表题和表注，不另加。
- 整体架构的流程用 Mermaid `flowchart LR` 画成从左到右的框图，一个模块一个框，不写成一行箭头。

- 数学符号、公式、变量一律用 LaTeX：行内 `$\alpha_i$`，独立公式 `$$…$$`。不用纯文本写上标下标。
- 细节粒度：保留能让读者理解设计或复现要点的数字（特征点数、主成分数、数据集规模、视角数、训练轮数），略去不改变理解的实现细节（卷积块数、通道数、FFN 维度、batch size、显卡型号）。判断标准是去掉它读者是否会误解方法。

### 长度

基础节的汉字数在 800 到 1500 之间，汉字数不计图片引用、链接和流程行，「针对关注点」「对比」两节另算、不设上限。超出时先压「背景」和「其他实验」，「一句话解释」「创新点」「消融」不压。

## 收尾

回复笔记的文件路径和「一句话解释」那一句。
