# 论文分享笔记模板

每节标题固定，括号里是该节的写作要求，写笔记时删掉。省略的节不占编号，实际出现的节从 1 连续编号。标题层级：文档名用 `#`，各节用 `##`，节内小标题用 `###`。正文里首次出现的模块名、指标名、方法名加粗。

---

# 论文分享：<方法名> —— <副标题>

（副标题从「一句话解释」里提炼，20 字以内，说这篇做成了什么。）

来源：arXiv:<id>（<机构，用「・」分隔>，<发表日期>）

（非 arXiv 论文写期刊或会议名与卷期，「论文」行给 DOI 链接。）

论文：<arXiv 链接>

代码 / 演示：<链接，没有写「未开源」>

## 1. 一句话解释做了什么

（一到两句，写成「输入 X → 输出 Y」的形象描述，让非本领域的人也能听懂。方法名之外不出现术语。）

![fig1](assets/fig1.png)

## 2. 背景、痛点与方法

### 背景

（≤2 条。这个任务是什么、为什么有人在意。）

### 痛点

（≤3 条。现有方法在这个背景下卡在哪里。每条痛点后面都要有一个创新点回应它。）

### 方法

（一段总述：这篇用什么思路解决上面的痛点。）

### 创新点

（≤3 条。每条写清「做了什么」和「回应哪条痛点」。每条以加粗的名字开头，如「**周期位置编码**：…」。）

## 3. 整体架构

（先用 Mermaid 从左到右的流程图列出每个模块，一个框一个模块，输入和输出用圆角框；框内文字短，不超过 12 字。再按模块逐条说明。）

```mermaid
flowchart LR
    IN([<输入>]) --> A[<模块 A>] --> B[<模块 B>] --> OUT([<输出>])
```

（按模块逐条说明：输入什么、做什么、输出什么。一个模块一条，条目以加粗的模块名开头。写到「这个模块的输入输出和核心操作」为止，层数、通道数这类实现细节不写；公式用 LaTeX。）

![arch](assets/arch.png)

### 训练与数据

（一小段。损失函数、训练轮数、数据集及其规模、对比的基线。）

## 4. 评价指标

（先逐条列出本节用到的指标，指标名加粗。后文直接沿用指标名。）

- **<指标一>**：<衡量什么，单位，方向>
- **<指标二>**：<衡量什么，单位，方向>

### 主指标（<原文表号>，<数据集>）

（放原文主指标表的截图，不自己重建表格。截图下方一到两句结论：SOTA 是谁、相对提升多少。只放一张。）

![table_main](assets/table_main.png)

<结论>

### 消融（<原文表号>）

（放原文消融表的截图，下方一两句说明哪些模块有效。论文消融只有文字没有表时写文字结论；没做消融就写「论文未做消融」。）

![table_ablation](assets/table_ablation.png)

<结论>

### 其他实验

（两三句话带过其余实验：做了什么、结论是什么，不放截图，详情指向原文表号。只有当某个实验直接验证了第 2 节的某条创新点、而主指标表和消融表都没覆盖时，才多放一张截图。）

## 5. 针对关注点：<用户的关注点>

（只有用户给了关注点才写。围绕关注点深挖，每个论断指向原文位置。关注点是「为什么」「是不是」这类机制问题时，用 `###` 分四块：作者的解释、论文有没有直接验证、推断（开头写明「论文未直接讨论，以下基于 X 推断」）、小结。关注点是某个具体设计或实验时，直接围绕它展开，末尾一句小结。）

## 6. 对比：本文 vs <对比论文方法名>

（只有用户给了对比论文才写。按用户给的维度做一张对照表，最后一行是结论。凭记忆写的内容标「未核对原文」。）

| 维度 | 本文 | <对比论文> |
|---|---|---|
| … | … | … |
| 结论 | … | |

## 7. 限制

（以作者自己承认的为主，一条一个。论文没有限制一节时第一条写「论文没有限制或未来工作一节」，再接作者散落在正文里的保留说法。skill 发现而作者未提的问题另起一条，开头标「补充（非作者所述）」。「后续方向」默认不写，只有作者给出具体可做的事时才加一条「作者提出的后续方向：…」。）

\#论文分享 #<主题标签 2 到 4 个>

# INDEX.md 格式

`~/Documents/论文分享/INDEX.md` 是全部笔记的汇总表，每篇一行，新笔记追加在末尾：

```
# 论文分享汇总

| 日期 | 论文 | 一句话 | 标签 | 笔记 |
|---|---|---|---|---|

```
