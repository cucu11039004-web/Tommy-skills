AI 刚完成一次功能升级，用户要尽快看懂这批代码做了什么，好接着推进。像聊天一样快：读够讲清所需的代码就开讲，一次回复讲一件事，往哪深入由用户的下一句决定。

## 读者

用户做 ML 研究：Python、深度学习代码直接讲设计意图，基础概念不解释。前端、部署、运维类代码对用户较陌生，其中的术语第一次出现时紧跟一句大白话解释。

## 步骤一：确定讲什么

- **点名了文件**（给了路径、文件名或选中的代码）：进步骤三，讲这个文件。
- **没点名**：确定改动范围，进步骤二。范围按以下顺序取第一个成立的：
  1. 用户说了范围（「最近两次 commit」「和 main 比」「从 abc123 之后」），照用户说的。
  2. 工作区或暂存区有未提交改动，取全部未提交改动（相对 HEAD）。
  3. 最近一次 commit。

完成标准：回复第一行写明讲的是哪个文件，或用的是哪个改动范围（如「范围：最近一次 commit `abc123 feat: …`」），用户看到不对可以马上纠正。

## 步骤二：改动总览

改动范围只涉及一个文件时，直接进步骤三讲它。

读改动范围内每个文件的 diff，需要时读文件全文，然后给出：

- 一句话说这次升级实现了什么功能。
- 文件清单：每个文件标新增或修改，一行说它在这次功能里负责什么。
- 串联关系：这些文件怎么配合完成功能，例如入口在哪、谁调用谁、数据从哪个文件流到哪个文件。文件超过三个时画一张文本流程图。

到此停下，不展开讲任何单个文件。

完成标准：范围内每个改动文件都在清单里，且出现在串联关系或被说明为独立改动。

## 步骤三：讲一个文件（总分总）

读这个文件的全文；它在改动范围内时，再读它在范围内的 diff。

1. **总**：几句话说清这个文件负责什么、由哪几块组成。
2. **分**：按函数、类或代码块讲。先过一遍整体结构，再重点讲这次新增或修改的部分。关键的几行单独引出，用 `路径:行号` 标出处。
3. **联动**：只讲它和这次改动范围内其他文件的关系：谁调用它、它调用谁、它的输出交给谁。只讲一层，更深的调用链留给用户追问。
4. **总**：一两句话收尾，说这个文件在这次升级里起什么作用。

完成标准：新增或修改的每个函数或代码块都讲到了；联动段列出了它和范围内其他文件的每一处直接关系，没有关系时写明「与本次其他改动无直接调用」。

## 偏差提醒

讲解中发现代码实际行为和命名、注释、commit 说明或用户说过的意图对不上时，单独用一段「偏差」指出：哪里写的是什么，实际做的是什么，出处在哪一行。没发现就不写这一段。

## 跑效果

讲解只靠读代码。用户要求看运行效果时才跑：优先用项目里现成的运行方式和小样例输入；训练、需要 GPU、下载权重或耗时较长的，先给出命令和预计耗时，等用户同意再跑。跑完停掉自己起的后台进程。

## 每次回复的结尾

列 2–3 个可以接着追问的方向，一行一个，写成用户可以直接回的问题，例如「想看 `compute_loss` 里 mask 是怎么生成的吗？」。总览之后的方向以「讲某个文件」为主。
